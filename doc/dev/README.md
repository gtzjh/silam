## 文件命名与分层

```text
SILAM模块：  <name>.silam.mod.f90
SILJA模块：  <name>.silja.mod.f90
主程序：     <name>.f90
化学机制：   cbm<N>_<detail>_<Component>.f90
```

生产源码按功能放在 `src/` 的子目录，三个独立测试程序放在 `tests/`；主程序 `src/silam_main.f90` 保留在根层。目录职责见[项目结构与架构](项目结构与架构.md)，历史文件名和模块名保持不变，新模块优先使用小写字母和下划线。

下面是历史分层的设计建议；功能目录不强制实现这些层次，现有源码也有跨层依赖，见[实际命名模式分析](实际命名模式分析.md)。

```text
✓ SILAM → SILJA → 基础层
✓ SILAM → 基础层
✗ SILJA → SILAM
✗ 基础层 → 任何上层
```

同层模块之间也应避免循环依赖。

## 常用编译命令

以下命令均在项目根目录执行：

```bash
# 首次编译：选择配置后构建
make -C src gnu
make -C src

# 增量编译
make -C src

# 清理重编
make -C src clean
make -C src

# 调试版本：切换配置后构建
make -C src gnu_debug
make -C src

# 独立测试程序：也可将 PROGRAM 改为 test_enkf 或 test_perturb
make -C build -f makefile.generic PROGRAM=test_modules SETUP=gnu
```

## Git工作流

默认在 `main` 开发，主目录保持 `main`。小任务直接执行；多阶段计划、跨模块协调、科学或数值行为变化等较大任务，先分析影响，再询问用户是否创建分支并放入 `.worktree/` 隔离。具体标准与操作见[开发流程](开发流程.md#任务大小与分支选择)。

agent 自行决定本地 commit 时机。隔离任务完成后，合并回 `main` 前必须获得用户明确同意；push 也必须获得用户明确同意。创建分支或 worktree 的同意不同时授权合并或 push。

提交前用 `git status` 检查改动，只提交本任务预期内容。`bin/`、`obj/`、`.tmp/`、`.worktree/` 和 `*.o`、`*.mod` 等编译产物不应提交。

## 添加新模块

1. 确定功能目录、模块职责及依赖方向，兼顾历史 SILAM/SILJA 命名。
2. 在 `src/` 对应功能目录创建文件，独立测试程序放在 `tests/`；参考[源码组织与命名](源码组织与命名.md)中的模块模板。
3. 实现并集成模块，使用 `make -C src` 编译验证。
4. 运行与改动相关的测试；toypoint案例的配置和运行方法见 [toypoint说明](https://github.com/fmidev/silam-toypoint)。
5. 更新受影响的文档，审查后按需要提交；隔离分支等待用户同意后再合并。

## 调试与常见问题

```bash
# 增加主线程和OpenMP线程的栈大小
ulimit -s unlimited
export OMP_STACKSIZE=100M
```

使用调试配置构建后，可通过 `gdb --args <可执行文件> <控制文件>` 调试。可执行文件位于 `bin/`，具体名称取决于构建配置。

| 问题 | 排查方向 |
|------|----------|
| 找不到模块文件 | 检查 `build/options.<配置名>` 中的库路径和编译器兼容性 |
| 循环依赖 | 检查 `build/silam_main.rules.full`，将共同依赖提取到独立模块 |
| 新模块编译失败 | 检查文件名、模块声明和依赖，必要时清理重编 |

| 文件 | 用途 |
|------|------|
| `src/silam_main.f90` | 主程序入口 |

| `src/Makefile` | 编译配置选择和构建入口 |
| `tests/test_*.f90` | 三个独立测试程序 |
| `build/makefile` | 构建系统 |
| `build/options.gnu` | GNU编译选项 |
