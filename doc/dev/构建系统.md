## 构建流程

### **标准编译过程**
```bash
# 从项目根目录执行
make -C src gnu        # 生成配置（首次或修改选项后）
make -C src            # 编译主模型
```

### **构建系统文件职责**

| 文件 | 职责 |
|------|------|
| `build/makefile` | 主控Makefile，处理依赖关系 |
| `build/options.*` | 平台特定编译选项（FFLAGS等） |
| `build/makefile.model` | 主模型构建规则 |
| `build/makefile.generic` | 独立测试程序构建规则 |
| `build/silam_main.rules.full` | 完整依赖关系（自动生成） |

### 工作树中的构建配置

默认在主目录的 `main` 开发，只有用户明确要求或同意隔离时才使用 `.worktree/`，参见[开发流程](开发流程.md#任务大小与分支选择)。

新工作树不继承主目录未提交、未跟踪或被忽略的配置和产物。首次编译前核对 `src/DefaultSetup`、`build/Makefile.branch`、依赖路径和所选平台配置。`src/Makefile` 选择构建配置，`build/Makefile.branch` 参与程序命名。

当前 `build/check_revision` 只从 `silam` 开头的 Git 分支名识别版本分支。开发分支名与程序版本名需要分别核对，不能假定任意任务分支都会自动生成正确的本地命名配置。构建通过情况以实际编译检查为准。

每个工作树使用自己的 `bin/`、对象文件、构建规则和运行输出。`build/makefile` 的对象目录受 `TMPDIR` 影响；设置该变量时，使用当前工作树内的任务临时目录，避免多个工作树写入同一对象目录。同一工作树内的配置生成和构建顺序执行。

## 添加新源文件的规则

### **自动识别机制**
主模型构建递归扫描 `src/` 中的 `.f90` 文件，并加入 `tests/numerics/test_fishpack_silam_impl.f90`，保留风场初始化的参考问题自检。通用程序构建递归扫描 `src/` 和 `tests/`。依赖生成器从指定主程序沿 `USE` 关系选择对象，再加入这些父模块对应的已扫描子模块实现；三个测试主程序不会混入主模型。

`build/config.pl` 保留完整源路径，识别 `module`、`program` 和直接父模块形式的 `submodule (parent) child`。子模块对象依赖父模块对象，使用父模块生成的 `.smod`。普通和完整依赖规则均通过 `-J` 将 `.mod`、`.smod` 写入对象目录；清理规则也移除 `.smod`。设置 `TMPDIR` 时，对象目录位于其 `obj/<SETUP>/`，可执行文件仍写入 `bin/`。

测试实现使用 Fortran 2008 子模块语法，需要编译器支持该特性；不增加构建工具或外部库依赖。GNU Fortran 11.4.0 已通过子模块访问私有宿主状态、链接选择及两种依赖规则的编译检查。

本地GNU Fortran 11.4.0对父模块私有过程的直接子模块调用存在链接限制，已用独立编译示例复现：目标过程可能只保留为局部符号或被优化移除。这与[GCC PR88632/104630的私有符号问题](https://gcc.gnu.org/pipermail/gcc-cvs/2026-August/460346.html)相符。相关父模块使用私有的 `procedure(原过程), pointer :: test_bind_* => 原过程` 绑定，测试子模块通过绑定调用，保留原有接口、可见性、计算例程及优化选项。

✓ **需要做的**：
1. 将生产源文件放入 `src/` 对应功能目录，测试放入 `tests/` 的同名功能目录
2. 遵循命名约定
3. 正确声明模块名，沿用现有模块与文件名的对应规则；历史例外见[实际命名模式分析](实际命名模式分析.md)

✗ **不需要做的**：
1. 手动修改Makefile添加文件列表
2. 手动声明依赖关系（会自动分析）

### **依赖关系自动生成**
```bash
# 构建系统会分析USE语句自动生成依赖
# 生成文件：build/silam_main.rules.full
```

版本信息模块 `src/revision.mod.f90` 和 `src/svndiff.mod.f90` 继续在构建时生成，不提交。

Git构建仍记录上游SVN标识和当前Git提交，但源码差异以当前Git HEAD为基线，范围包含 `build/`、`src/` 和 `tests/`，避免跨目录改名后将整份源码嵌入版本模块。差异文本允许历史注释中的非UTF-8字节，替换不可解码字符；这只影响构建元数据，不改写原始源码。与原机制相同，未跟踪文件不属于 `git diff` 的覆盖范围。

### 测试子模块

`tests/` 镜像 `src/` 的功能目录，每个父模块对应一个 `test_<父模块名>_impl.f90`。父模块保留接口，测试实现通过子模块宿主关联访问原有私有实体，不需要将内部类型和状态改为公开。

使用现有通用入口编译并链接全部29个测试子模块：

```bash
make -C build -f makefile.generic PROGRAM=silam_main SETUP=gnu
```

该入口生成 `bin/silam_main.gnu`，仅用于验证所有测试实现可编译和链接，不自动执行测试。子模块按父模块依赖闭包选择，主模型常规入口只加入FISHPACK自检实现。目录与运行限制见[测试目录说明](../../tests/README.md)。

### 独立测试程序

选择配置后，从项目根目录构建所需入口：

```bash
make -C build -f makefile.generic PROGRAM=test_modules SETUP=gnu
make -C build -f makefile.generic PROGRAM=test_enkf SETUP=gnu
make -C build -f makefile.generic PROGRAM=test_perturb SETUP=gnu
```

这些命令只构建测试程序。运行所需的外部输入、运行目录和结果判据见[测试与调试](测试与调试.md)；编译完成不等于测试或数值回归通过。

### 花粉用途的构建范围

当前保留 GNU 普通、调试、MPI 和 MPI 调试配置，以及主模型、通用测试程序构建和源码打包入口。
KPP 生成器及模板、箱模型、火灾预处理、独立格式转换和滞后输入工具已移除，对应构建目标也已移除。

`src/chem/` 下四个机制子目录中的 `cbm*.f90` 和 `chem_dep_cbm*.f90` 是已有的化学机制实现，仍被公共过程管理器引用，必须提交并保留。
普通编译直接使用这些源码，不再提供 KPP 重新生成机制的工作流。恢复生成器和独立工具时，可从精简前的 Git 版本取回其源码与构建规则。

当前分发不含 `photolysis_finrose.dat`。花粉和 toypoint 配置未启用 CBM 光化学，已去掉其未使用的光解表设置；
启用 CBM 的其他案例仍需要自行提供兼容光解表。物质数据库、光学属性表、共享混合物表和气象名称表继续保留。

### 源码打包

在项目根目录执行 `make -C build SETUP=gnu distr`，生成 `distr/` 下的源码包。
打包复制现有版本模块和本地构建配置，不改写活动工作树的 Fortran 源码；包内不含版本控制元数据，也不重新生成版本模块。
打包保留 `src/` 功能目录和 `tests/` 测试入口，包含项目说明、执行规则和开发文档，不包含编译器、外部库、toypoint 案例、用户输出和外部花粉输入数据。

## 编译选项配置

### **平台选择**
```bash
# GCC编译器
make -C src gnu
make -C src

# GNU调试配置
make -C src gnu_debug
make -C src

# MPI并行版本
make -C src gnumpi
make -C src

# MPI调试版本
make -C src gnumpi_debug
make -C src
```

### **自定义编译选项**
编辑`build/options.<SETUP>`：
```makefile
# 优化级别
OPTIMIZATION = -O3 -fopenmp -ffast-math

# 调试选项
DEBUG = -g -fbacktrace

# 预处理器定义
PREPROCESS = -x f95-cpp-input -D WITH_BZIP2 -DUSE_PROJ6

# Include路径
INCLUDE = -I$(OBJDIR) -I/usr/include
```
