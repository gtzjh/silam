## 测试与验证

### 测试策略

按改动行为和风险选择检查，不要求每次运行所有配置。文档修改通常只检查内容、链接和格式；模型源码修改需要相关编译检查。昂贵实验和输出再生成保持在用户授权范围内。

| 验证层次 | 检查内容 | 结论范围 |
|----------|----------|----------|
| 环境检查 | 实际编译器、依赖、配置与所需接口 | 环境是否满足本次任务需要 |
| 编译 | 本次修改涉及的模型、工具和构建配置 | 这些目标是否成功构建 |
| 案例运行 | 退出状态、运行诊断及预期输出 | 该案例的基本流程是否完成 |
| 数值回归 | 固定输入和参考输出下的定量比较 | 指定变量是否满足约定的误差标准 |

分别报告已通过、失败及未执行或无法执行的检查。未完成的检查写为 **未验证（NOT VERIFIED）**，并说明原因。编译成功、案例跑通或生成文件分别报告，不能直接作为数值一致的依据。

#### **编译测试**

以下命令从当前工作树根目录执行。先选择本次需要的配置，再构建；接口或依赖变化时按需要清理重编。

```bash
# GNU配置示例
make -C src gnu
make -C src

# 需要调试检查时，切换配置后构建
make -C src gnu_debug
make -C src
```

#### **运行时测试**

仓库中的 `silam-toypoint/` 提供案例和输入。运行前将案例复制到当前工作树的任务临时目录，调整 `ini` 链接或 `standard_setup_directory`，指向该工作树的 `ini/`；输出也留在任务目录。保留原有输入与参考结果。

下面说明调用形式，需将可执行文件路径替换为实际路径，并从临时案例副本运行：

```bash
/path/to/active-worktree/bin/silam_v6_1pub.gnu toypoint_mpi.control

# 结合退出状态和运行诊断检查输出
ls output/
```

案例配置说明见 [toypoint说明](https://github.com/fmidev/silam-toypoint)。源码包不包含该独立案例，使用时需另行获取。
已有输出文件的存在不代表本轮执行过案例。

#### 数值回归

涉及科学结果的修改应明确以下内容，再执行定量比较：

- 输入数据、参数、参考代码版本和参考输出，以及必要的数据标识。
- 待比较变量、单位、维度、比较范围、误差指标和容差。
- 当前代码版本、编译器及选项、依赖版本和运行设置；并行运行还需记录进程数与线程数。

参考输出按原样保留；修改数值基线或验收标准前先与用户讨论。缺少输入、参考结果或运行条件时，记录未验证及具体缺口。需要长期保留的验证方法和结论写入对应开发文档，不建立独立任务日志或 MEMORY。

#### 接口与运行行为

- FISHPACK的 `TBLKTRI` 实现在 `tests/numerics/`，正常模型仍链接它。[风场诊断初始化](../../src/diagnostics/diagnostic_variables.silam.mod.f90#L272) 中的调用、参考问题和容差保持原样。
- 私有的 `Train_in_cell`、清除例程、平流内核、`CMrelax`、DMS源分量、同化状态和光解查找表保留在生产模块。测试子模块可以访问这些宿主实体，不需要将其改为公开。
- 时间、物质转换、观测和伴随测试的内部辅助过程随外层测试整体移动，保留宿主变量访问。原来的光解内部测试现在是私有的 `test_interp_weights()`，测试运算保持一致。
- 为兼容GNU Fortran 11的私有过程链接限制，相关父模块保留私有 `test_bind_*` 过程指针；测试通过这些绑定调用原计算过程，参数、计算及生产调用保持一致。

## 常见问题与解决方案

### 编译问题

#### **问题：找不到模块文件**
```
Error: Can't open module file 'grib_api.mod'
```

**原因**：系统库的.mod文件不在编译器搜索路径

**解决**：
```bash
# 方法1：修改build/options.gnu
INCLUDE = -I$(OBJDIR) -I/usr/lib/x86_64-linux-gnu/fortran/gfortran-mod-15

# 方法2：创建符号链接
sudo ln -s /usr/lib/x86_64-linux-gnu/fortran/gfortran-mod-15/grib_api.mod \
           /usr/lib/gcc/x86_64-linux-gnu/10/finclude/
```

#### **问题：循环依赖**
```
Error: Circular dependency detected
```

**排查步骤**：
1. 检查`build/silam_main.rules.full`中的依赖链
2. 重构代码，将共同依赖提取到独立模块
3. 使用接口抽象打破循环

### 运行时问题

#### **问题：栈溢出**
```
Segmentation fault (core dumped)
```

**解决**：
```bash
# 增加栈大小
ulimit -s unlimited

# 或使用OpenMP线程栈控制
export OMP_STACKSIZE=100M
```

#### **问题：内存不足**
**优化策略**：
- 减少模拟域大小
- 降低垂直层数
- 减少物种数量
- 使用MPI分布式计算

### 集成问题

#### **添加新模块后编译失败**

**检查清单**：
```bash
# 1. 文件名是否正确
ls -l src/chem/your_module.silam.mod.f90

# 2. 模块名是否匹配
grep "^module" src/chem/your_module.silam.mod.f90

# 3. 依赖是否正确
grep "use " src/chem/your_module.silam.mod.f90

# 4. 重新生成依赖关系
make -C build SETUP=gnu config

# 5. 完全重新编译
make -C src clean
make -C src
```
