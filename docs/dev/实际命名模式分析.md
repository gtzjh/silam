# SILAM项目实际命名模式分析

当前维护 187 个 `.f90` 源文件，其中 155 个在 `src/`，`tests/` 按同名功能目录包含29个测试子模块和三个独立程序。原有生产文件名不变，测试子模块使用 `test_<父模块名>_impl.f90`，其单元名与文件名一致。历史文件名仍包含以下变体：

## 实际命名模式

### 1. 标准模块命名
```
<module_name>.silam.mod.f90     # SILAM层模块（52个）
<module_name>.silja.mod.f90     # SILJA层模块（32个）
```

### 2. 允许的变体
```
<name>_v<N>.silam.mod.f90       # 带版本号
<name>_<N>.silja.mod.f90        # 带数字后缀
<name>_<detail>.silam.mod.f90   # 带详细描述
```

### 3. 特殊模块（无层次标识）
```
<name>.mod.f90                  # 其他模块（15个）
例如：
- silam_units.mod.f90
- chemical_setup.mod.f90
```

### 4. 允许的字符
- 小写字母
- 数字
- 下划线
- **大写字母**（在缩写中，如NH3, FAN）

### 5. 化学机制命名
```
cbm<N>(_strato)?_SOA_<Component>.f90
cbm<N>(_strato)?_SOA_interface.mod.f90
chem_dep_cbm<N>(_strato)?_SOA.mod.f90
```

## 分层依赖问题

历史 SILJA/SILAM 命名没有形成严格的依赖层次，例如：
```
source_terms_bomb.silja.mod.f90  → source_terms_time_params
source_terms_volcano.silja.mod.f90 → source_terms_time_params
dispersion_models.silja.mod.f90 → da_driver、ensemble_driver
```

前两个源模块与 `source_terms_time_params` 同在 `src/emissions/`，而 `src/transport/dispersion_models.silja.mod.f90` 调用 `src/assimilation/` 中的驱动模块。功能目录描述代码职责，不声明也不强制新的分层关系；不能仅按文件后缀推断依赖方向。本次只迁移路径，保留这些既有依赖。

## 建议

**对于新代码**：
- 遵循 `<name>.silam.mod.f90` 或 `<name>.silja.mod.f90` 格式
- 使用小写字母和下划线
- 避免数字和版本号（除非必要）

**对于现有代码**：
- 理解这些历史命名模式
- 不强制重命名（避免破坏现有依赖）
- 保持一致性
