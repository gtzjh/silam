# 构建与调试

保留现有的 Make 和平台工作流程。只有用户采用容器工作流程时，才要求使用容器。

## 安装与构建

Ubuntu 依赖安装：

```bash
sudo apt install make perl gfortran libeccodes-dev libnetcdf-dev libnetcdff-dev liblapack-dev libblas-dev libbz2-dev libproj-dev
```

根目录 [Makefile](../Makefile) 是日常入口，所选配置保存在本地 `build/DefaultSetup`；库路径和编译选项见 `build/options.<配置名>`。测试子模块要求编译器支持 Fortran 2008。

```bash
make gnu       # 选择配置；也可选择 gnu_debug、gnumpi、gnumpi_debug
make           # 首次或增量构建
```

默认生成 `bin/silam.<配置名>`，并更新 `bin/silam` 软链接。`make what` 查看配置，`make clean` 清理，`make full` 使用完整依赖和 8 个并行编译任务。

### 构建机制

- 根目录 `Makefile` 将配置选择写入本地 `build/DefaultSetup`，再调用内部构建。该文件不提交。
- `build/makefile` 递归扫描 `src/` 中的 `*.f90` 文件，另加入 `tests/numerics/test_fishpack_silam_impl.f90`。
- `build/makefile.generic` 递归扫描 `src/` 和 `tests/` 的 `*.f90`。
- `build/config.pl` 识别 `module`、`program` 和 `submodule (parent) child` 形式。
- 从指定主程序沿 `USE` 依赖选择对象，再加入父模块在依赖闭包内的子模块。
- `make` 使用 `RULES=simple`，普通模块规则主要依赖自身源码；`make full` 使用完整依赖规则，并传入 `-j 8`。
- 默认对象目录为 `obj/<SETUP>/`；设置 `TMPDIR` 后为 `<TMPDIR>/obj/<SETUP>/`。
- 构建读取当前工作树源码，包括未提交修改；不嵌入提交号、编译机器、路径或时间。

## 问题排查

| 现象 | 检查位置 |
|---|---|
| 找不到 `grib_api.mod` 或其他库模块 | 核对 gfortran 与库模块兼容性，并在 `build/options.<配置名>` 配置实际包含路径 |
| 新源码未纳入构建或依赖错误 | 核对小写 `.f90` 扩展名、模块声明和 `build/silam_main.rules.full` |
| 栈空间不足 | 核对主线程栈及 `OMP_STACKSIZE` |

调试可使用 `gnu_debug` 配置及 `gdb --args <可执行文件> <控制文件>`。

运行方式与案例见[运行与配置](运行与配置.md#toypoint)。
