# 版本管理

## 分支与 Git 操作

- 默认在 `main` 上开发，主工作树保持在 `main` 分支。
- 对于较大的任务，在首次编辑前询问用户是否创建分支并使用工作树。出现以下任一情况时，需要询问：
  - 多个功能模块需要协调修改接口、共享数据或调用流程。
  - 模块职责、公共接口、数据格式、工具链或依赖发生变化。
  - 科学公式、单位、关键数值方法、精度或并行计算行为发生变化。
  - 验证范围显著扩大，或测试验收标准、数值参考结果发生变化。
- 只有用户要求或同意所提议的隔离方案后，才创建分支或工作树。如果用户选择 `main`，则继续在该分支上工作。
- 隔离工作完成后，报告修改内容、检查结果及局限。将其合并到 `main` 前，等待用户明确批准。
- 推送始终需要用户明确批准。

## 工作树

- 将工作树放在项目根目录的 `.worktree/<任务名或分支名>/` 下。
- 除非用户指定其他基线，否则从已提交的 `main` 创建新的任务分支。
- 构建配置和运行输出保留在对应工作树内。如果设置 `TMPDIR`，将其指向该工作树的任务临时目录。
- 集成完成后，先保存交付成果再清理。使用 `git worktree remove` 移除已完成的工作树，然后删除其已合并的任务分支。
